# Как устроен SPACE

Здесь описано, как устроен проект и почему он сделан именно так. Как его запустить, написано в [README](../README.md).

## Коротко

- **Один процесс Node.js** на одном порту отдаёт собранный клиент, HTTP API (`/api/*`) и WebSocket для совместной работы (`/collab`). Внешних сервисов нет. База данных — встроенный `node:sqlite`, файлы лежат в папке на диске.
- **Доска — это документ Yjs (CRDT)**, и он единственный источник истины. Клиент правит его у себя сразу, без ожидания сервера. Правки нескольких людей сливаются автоматически: без конфликтов и блокировок, в том числе после работы без сети.
- **Клиент написан на Svelte 5 с рунами.** У каждого узла доски есть зеркало с реактивными полями. Изменилось одно поле — обновляется только та часть DOM, которая от него зависит.
- **Отрисовка идёт на трёх уровнях детализации.** Вблизи узлы — обычные DOM-элементы, в среднем плане — их упрощённые версии, а издалека вся доска рисуется на одном `<canvas>`.

## Схема

```
БРАУЗЕР
  Svelte UI: главная, экран доски, панели, меню, диалоги
    │  читает реактивное состояние, вызывает действия
    ▼
  Board: камера, инструменты, жесты (Interact), присутствие
    │
    ▼
  BoardStore: NodeView на каждый узел ──► DOM (near/mid) или <canvas> (far)
   │ ▲
   │ │  вниз: transact(LOCAL) + UndoManager; вверх: observeDeep
   ▼ │
  Y.Doc ──► y-indexeddb (копия доски на устройстве)
    │
    │  WebSocket /collab: обновления Yjs, курсоры и выделения (awareness)
    ▼
СЕРВЕР (Node ≥ 22.18, один процесс и один порт)
  Hocuspocus /collab: права при подключении, зритель только читает,
                      открытые доски в памяти
  Hono /api/*:        вход, доски, участники, история, файлы, превью ссылок;
                      запросы интерфейса с кукой space_sid и x-space: 1
  статика:            dist с готовыми .br/.gz, /assets с вечным кэшем
    │  сохранение через 1,5 с после правки (не реже раза в 8 с)
    ▼
  storage/space.db (SQLite, WAL) · files/ab/<sha256> · thumbs/<id>.webp
```

## Путь одной правки

1. Человек тащит карточку. `Interact` превращает нажатие в «жест» (`move`, `resize`, `connect`, `ink`…) и сдвигает `NodeView` прямо в памяти — каждый кадр, без записи в документ.
2. Примерно 20 раз в секунду и ещё раз в конце жеста `BoardStore` пишет позиции в `Y.Doc` одной транзакцией с меткой `LOCAL`. Такие правки попадают в `Y.UndoManager`, поэтому весь жест отменяется одним `Ctrl+Z`. Служебные правки (замер высоты, превью ссылки) пишутся с другой меткой и в отмену не попадают.
3. Из `Y.Doc` правка уходит двумя путями: в IndexedDB (`y-indexeddb`) и на сервер через `HocuspocusProvider`.
4. Сервер применяет обновление к документу в памяти и рассылает его остальным участникам. Через 1,5 секунды без правок (и не реже раза в 8 секунд) документ целиком сохраняется в SQLite.
5. У других участников `BoardStore` получает событие `observeDeep` и меняет только затронутые поля их `NodeView`. Svelte перерисовывает только то, что от этих полей зависит.

Курсоры, выделения, штрихи пера и указка других людей передаются через awareness Hocuspocus (не чаще ~30 раз в секунду) и в документ не записываются.

## Модель данных

```

├─ meta:  Y.Map   { title, createdAt, bg (фон доски), font (шрифт доски) — общие для всех }
├─ chat:  Y.Array сообщения чата доски { id, uid, name, color, text, t, refs? }
└─ nodes: Y.Map<id, Y.Map>     один узел = одна Y.Map с плоскими полями
     type     note | text | code | image | video | audio | file | shelf | link | frame
              | shape | path | ink | sticker | table | task | poll | timer
              | counter | dice | progress | comment
              | button | switch | slider | rating | clock | countdown | chart | qr
              | wheel | status | tracker | calc | gate
              | stopwatch | coin | flipcard | deck | random | score | turns | buzzer
              | checklist | input | calendar | icon | token | words | spoiler
              | kanban | roadmap | stats | loot | curve | palette | tilemap | estimate
     x y w h  мировые координаты и размер
     r        поворот
     z        порядок — дробный индекс (fractional-indexing)
     parent   рамка, в которой лежит узел (рамки вкладываются друг в друга)
     text     Y.Text — текст заметки, кода, подписи
     …        свойства типа: color (имя палитры или #rrggbb), opacity, font, size,

              bc/bw/bs обводка, rad скругление, shd тень, fx анимация, flip, flt фильтр,
              tag/tagc метка, hid — спрятан (зрителям не виден, редакторам — призраком)
     начертание (узлы с текстом): tw толщина, ti курсив, tt прописные / капитель,
              tls и tlh интервалы между буквами и строками, tfx эффект текста
     dev      рамка-устройство: phone | tablet | browser | window | game
     lg       правило логики на стрелке: { on, do, n?, x?, tn?, tx?, rev? }
     «личные» поля — у каждого участника своё, поэтому одновременные правки не теряются:
     vote:<uid>     голос в опросе        d:<uid>   поправка счётчика (сумма = n0 + Σd)
     m:<ключ>       сообщение комментария c:<строка>:<столбец>  ячейка таблицы
     rt:<uid>       оценка звёздами       k:<i>     отметка клетки трекера
     pp:<uid>       карта покера планирования
     по записи на поле — двое правят разные записи без потерь:
     kc:<id> карточка канбана   rb:<id> этап дорожной карты   gt:/go:<x>:<y> клетка карты уровня
     разовые события — счётчик + кто: press (кнопка), spin (колесо), fxe (эффект логики)
```

- **Поля сливаются независимо.** Один человек меняет цвет карточки, другой в это время её двигает — сохраняются обе правки. По той же причине у голосов, поправок счётчика и сообщений комментариев — отдельные поля на каждого: двое жмут «+» одновременно — счётчик увеличится на два.
- **Текст хранится в `Y.Text`.** Если двое пишут в одну заметку одновременно, буквы не теряются. Редактор (CodeMirror) подключён к тексту через `y-codemirror.next`.
- **`z` — дробный индекс.** «Поднять наверх» меняет одно поле одного узла, а не перенумеровывает все узлы.
- **Рамки.** `parent` — ближайшая рамка (`containerOf`): обычный узел лежит в той, куда попал его центр, рамка — в той, что вмещает её целиком и больше её; из подходящих — самая тесная, поэтому рамки вкладываются. Перенос рамки уносит всех её потомков (`descendants`). После жеста `reparent` пересчитывает принадлежность только у сдвинутых узлов, и узел, ехавший вместе со своей рамкой, остаётся в ней, даже если вылез за край.
- **Привязки стрелок** (`b0`, `b1`) хранят id цели и точку на её рамке в долях (u, v). Поэтому стрелка следует за фигурой у всех участников. Маршруты (прямая, кривая, под прямым углом) строит `connector.ts`.
- **Чат** — отдельный `Y.Array` в том же документе: сохраняется вместе с доской и работает без сети, но правки чата не попадают в отмену и не копируются в дубликат доски.
- Схема описана в `src/shared/doc.ts`, поля и значения по умолчанию — в `src/client/board/model.ts`. Экспорт доски (`.space`) — это `Y.encodeStateAsUpdate`, то есть ровно то, что хранит сервер.

### Сервер (SQLite)

`users` (с рангом `rank` и `banned_at`), `sessions`, `login_links`, `boards` (в том числе `state` — документ доски и `settings` — настройки доски в JSON), `members` (роль или блокировка), `board_links` (ссылки-приглашения на доску), `invites` (приглашения на сервер), `settings` (настройки сервера одной записью JSON), `snapshots`, `files`, `unfurls`. Схема описана в `src/server/db.ts` через `CREATE TABLE IF NOT EXISTS`; новые столбцы в старых базах добавляет `addColumn` (через `PRAGMA table_info`), так что обновление не требует миграций вручную. Самый первый аккаунт становится владельцем сервера. База работает в режиме WAL с `synchronous = NORMAL`.

## Отрисовка

| Уровень | Когда | Что на экране |
| --- | --- | --- |
| `near` | масштаб ≳ 0,4 | настоящие узлы: Markdown, код, видео, iframe, редактор |
| `mid` | ~0,16–0,4 | те же DOM-узлы в облегчённом виде: без теней и мелких кнопок, вместо картинок — уменьшенные превью |
| `far` | < 0,16 **или** в зоне отрисовки больше 700 узлов | вся доска на одном `<canvas>` (`scene.ts`), DOM-узлов нет |

- **Гистерезис.** У каждого порога есть запас, поэтому уровень не переключается туда-обратно на границе. На плотной доске режим `far` включается раньше (порог 700 узлов, выключается ниже 480): DOM из тысяч узлов не может двигаться плавно.
- **Отсечение (`camera.cull`).** В DOM есть только узлы в прямоугольнике экрана с запасом. Прямоугольник пересчитывается, лишь когда экран выходит за запас или заметно меняется масштаб, поэтому при обычной прокрутке DOM не трогается.
- **Постепенное появление.** Узлы монтируются пачками по 80 за кадр, сначала ближайшие к центру. Пока пачки догружаются, под ними виден холст `far`, так что пустых мест нет.
- **Слои.** Мир — один элемент с `transform` камеры. Сетка — один элемент чуть больше экрана с CSS-фоном: он сдвигается на остаток от шага, а при масштабе растягивается `transform`, и фон перерисовывается, только когда шаг изменился больше чем на 12%. Свечение (`Glow`) — холст в координатах мира: при прокрутке он просто едет вместе с доской. Ручки, рамка выделения, направляющие и чужие курсоры (`Overlay`) рисуются в экранных координатах.
- **Один отрисовщик на всё.** `shapes.ts` строит контуры фигур, стрелки и штрихи пера. Те же функции рисуют DOM-узлы, предпросмотр и холст, поэтому фигура выглядит одинаково при любом масштабе. `scene.ts` рисует дальний план, превью досок на главной и мини-карту. Новые объекты (кнопка, переключатель, ползунок, диаграмма, колесо…) издалека рисуются упрощёнными мини-версиями (`drawWidget`), а не серыми прямоугольниками, и учитывают оформление (`fillOf`: своя заливка и обводка). Спрятанные логикой узлы на превью и у зрителей не рисуются, у редакторов — полупрозрачные.

## Производительность

- **Тонкая реактивность.** Правка одного поля не трогает остальные узлы. Готовый HTML Markdown и подсветки кэшируется в `NodeView`: узел уходит из DOM и возвращается без пересчёта, пока не изменился его текст.
- **Переходные перетаскивания.** Пока длится жест, документ не пишется на каждый кадр, и сеть не забивается сотнями мелких обновлений.
- **Движение камеры.** Мир двигается одним `transform: translate3d(…) scale(…)` без `will-change`: с ним браузер растягивал готовую картинку слоя, и при масштабе всё сначала «мылилось», а резким становилось с задержкой. Обратный масштаб `--iz` (обводки, подписи и ручки постоянной экранной толщины) не ставится на весь мир — иначе каждый кадр масштаба пересчитывал бы стили тысяч элементов. Он есть у слоя рамок и у тех узлов, которым нужен прямо сейчас (выделенные, под указателем, чужие выделения, комментарии, правка линии), и меняется плавно, без ступеней; остальным линиям `izIdle` обновляется, когда камера остановилась. Свечение во время движения не пересчитывается.
- **Пространственный индекс** (`spatial.ts`): мир разбит на клетки 512×512, у клетки — список задевающих её узлов. Наведение, поиск рамки под узлом и выборка «что в прямоугольнике» смотрят только соседей, а не всю доску; изменённый узел переиндексируется при ближайшем запросе.
- **Свечение под группами** считается в фоновом потоке (`glow.worker.ts`) и только когда прямоугольники узлов действительно изменились.
- **Отсечение с запасом по масштабу.** Прямоугольник отсечения пересчитывается при смене масштаба больше чем в 2,6 раза, поэтому при плавном приближении узлы не выгружаются и не монтируются заново.
- **Холст `far`** перерисовывается только при правке документа, смене выделения или камеры. На мелком масштабе карточки — простые прямоугольники, а невидимые полосы текста пропускаются.
- **Фоновая работа в простое.** Превью доски рисуется через `requestIdleCallback`, и только когда камера стоит и нет активного жеста.
- **Картинки.** Вблизи узел показывает уменьшенное превью и подменяет его оригиналом, только когда картинка на экране крупнее ~760 физических пикселей, — и решение принимается, когда камера остановилась, с запасом в обе стороны (обратно на превью — меньше ~420 px). Так при масштабировании не декодируются мегабайты на каждом шаге. Новая картинка показывается, только когда уже декодирована (`img.decode()`), без мигания. GIF анимируется только вблизи и у выделенного; издали — неподвижный первый кадр (это превью браузер делает при загрузке). На холсте дальнего плана картинки рисуются из уменьшенных копий (`createImageBitmap` 64/160/400 px), а не масштабированием оригинала на каждом кадре.
- **Без `backdrop-filter`.** Размытие под панелями пересчитывается на каждом кадре прокрутки и съедает FPS.
- **Ленивые чанки.** Редактор CodeMirror, подсветка (lezer и языки), KaTeX и fflate грузятся при первой надобности. Пока чанк не догрузился, виден исходный текст.
- **Сборка.** `scripts/precompress.ts` кладёт рядом с каждым файлом `.br` (quality 11) и `.gz`. Сервер отдаёт их без сжатия на лету, а `/assets/*` — с `Cache-Control: immutable`.

Размеры (brotli): старт приложения — 52 КБ JS и 19 КБ CSS, экран доски — ещё 268 КБ JS и 29 КБ CSS. Подсветка (83 КБ), редактор, KaTeX и шаблоны (27 КБ) грузятся отдельно. Шрифты (18 семейств, `@fontsource`) объявлены через `@font-face` с `unicode-range`: браузер скачивает файл шрифта, только когда на экране есть текст этим шрифтом, и только нужное подмножество (латиница, кириллица).

Замер на 5059 узлах (`tests/e2e/perf.ts`, headless Chromium без GPU): синхронизация ~1 с, прокрутка вблизи ~54 FPS, издалека ~53 FPS, приближение ~48 FPS, отдаление до всей доски ~35 FPS.

## Общение

- **Чат доски** (`social.svelte.ts`, `chrome/Chat.svelte`) — `Y.Array` «chat» в документе (см. выше). К сообщению можно приложить выделенные объекты (`refs`): щелчок по вложению показывает их. Непрочитанные считаются локально; новое сообщение при закрытом чате всплывает у кнопки.
- **Сообщение у курсора, реакции, «позвать всех»** идут через awareness Hocuspocus — мгновенно и без следа в документе. Поле `say` — текст у курсора (пока человек печатает и ещё несколько секунд), `react: { e, x, y, id }` — эмодзи, летящие из точки, `summon: { id, view }` — просьба ко всем перелететь к моему виду. Повторы отсекаются по возрастающему `id` для каждого `clientId`.
- **Комментарии** — узел `comment` (булавка постоянного экранного размера) с веткой сообщений в полях `m:<ключ>`; ветка открывается панелью `CommentThread`.
- **Игровые объекты** (`nodes/games.ts`, `nodes/play.ts`): счётчик — база `n0` плюс личные поправки `d:<uid>`, с границами `min`/`max` (прибавка упирается в границу, а не проскакивает её); кубик хранит последний бросок целиком (кто, когда, грани, номер броска); прогресс — значение и число этапов. Очки табло (`sc:<игрок>`), нажатия «Кто первый?» (`bq:<uid>`), слова облака (`w:<uid>:…`) и отметки календаря (`k:<день>:<uid>`) лежат в отдельных полях, поэтому одновременные нажатия не теряются. Монетка, колода и случайный выбор записывают результат вместе с номером броска; анимацию у всех запускает смена номера, а её «случайность» выводится из него же — у всех участников она одинаковая.
- **3D-кубик** (`nodes/die3d.ts`) рисуется в SVG, без CSS 3D: поворот — матрица 3×3, проекция ортогональная. Видимые грани — квадраты с точками, наложенные аффинной матрицей, их яркость — по нормали и направлению света; скруглённые рёбра и углы — выпуклая оболочка внутреннего куба, обведённая толстой линией со скруглёнными стыками (это и есть силуэт скруглённого куба). Бросок — покадровый поворот вокруг оси поперёк движения, остаток которого тает к нулю: в конце кубик ровно в позе «лёжа», которая рисуется и без анимации. Подпрыгивание и тень — отдельные анимации WAAPI.

## Логика

- **Правило живёт на стрелке** (`lg` у узла `path`, оба конца которого привязаны к разным объектам): событие источника (`on`) → действие с целью (`do`), с числом (`n`), выбором (`x`: цвет, эффект, текст, статус), порогом события (`tn`), выбором события (`tx`) и флажком «отменять при обратном событии» (`rev`). Словарь событий и действий для каждого типа — `triggersFor` / `actionsFor` в `board/logic.svelte.ts`; `suggestRule` подбирает разумное правило, когда стрелку только провели.
- **Кто выполняет.** Движок подписан на изменения документа и реагирует только на **свои** (локальные) правки: событие находит тот, чьё действие его вызвало, и записывает результат обычной транзакцией. У остальных результат просто приходит вместе с документом, поэтому правило не срабатывает дважды. Действия логики попадают в ту же отмену (`Ctrl+Z`), что и вызвавшее их действие.
- **Производные значения** («доля выполненного», «считать выполненные», «все готовы», «Вычисление», «Логический блок») полностью определяются входами. Их досчитывает любой участник, запись у всех одинаковая, так что расхождений нет. Входы узла — все стрелки, которые к нему ведут (`inputsOf` в `nodes/values.ts`); их значения приводятся к числу (`numValue`) или к «готово / не готово» (`doneShare`, `isOn`).
- **Цепочки и циклы.** Результат одного правила может запустить следующее (кнопка → кубики → счётчик). Глубина цепочки ограничена 12 шагами, поэтому зацикленные стрелки не вешают доску. Действия после анимации (бросок кубиков, вращение колеса) ждут её конца.
- **Видно на стрелке.** Стрелка с правилом получает подпись-значок (`ruleSummary`), бегущий пунктир и искру при срабатывании. Настраивается правило во вкладке «Логика» панели настроек (`chrome/inspector/LogicTab.svelte`; кнопка ⚡ над стрелкой или пункт меню «Логика стрелки…»).

## Панель настроек

- `chrome/Inspector.svelte` — панель справа (на телефоне — лист снизу) с вкладками «Настройки», «Оформление», «Логика». Открывается клавишей `I`, двойным щелчком по виджету, кнопкой «Настроить» или пунктом меню; пока открыта, занимаемое место (`b.inset`) учитывают камера и панель над выделением.
- Что показать, решает `inspect/build.ts`: `inspectFor(b, views)` возвращает разделы с полями (типы — `inspect/types.ts`): переключатель, число, текст, выбор, цвета, эмодзи, значок, список строк (варианты, игроки, пункты, грани), длительность, кнопки действий. Поле — объект с `get`/`set`; запись идёт сразу во все выделенные объекты этого типа одной транзакцией. Элементы — в `chrome/inspector/` (`Field`, `DurField`, `ListEdit`, `ColorDots`, `EmojiField`, `IconField`).
- `DurField` принимает время полями (дни, часы, минуты, секунды) или текстом: разбор и вывод — `parseDur` / `durText` в `nodes/timer.ts`.

## Оформление

- Поля оформления (`fc`, `tc`, `bc`, `bw`, `rad`, `shd`, `fx`, `flip`, `flt`, `tag`, `hid` и др.) есть у любого узла и превращаются в CSS-переменные и классы на обёртке узла в `NodeHost`, поэтому типам узлов не нужно знать о них по отдельности. Что поддерживает тип (заливку, рамку, фильтры, отражение), решают `canFill`, `canBox`, `canFilter`, `canFlip` в `board/style.ts`.
- **Шрифт и начертание.** Шрифт узла — поле `font` (список и группы — `FONTS` в `model.ts`); если его нет, узел с текстом берёт шрифт доски `meta.font`, а явно выбранный «Обычный» важнее шрифта доски. Начертание (`tw`, `ti`, `tt`, `tls`, `tlh`, `tfx`) — классы на обёртке узла; правила в `styles/custom.css` действуют только на текстовые части (заметка, текст, подписи фигур, линий и рамок). Обводка и «объём» берут цвет, контрастный тексту (`oklch(from currentColor …)`), или цвет рамки, если она задана. Выбор шрифта — меню с образцом каждого шрифта его же начертанием (`fontItems` в `menus.ts`), поле «Шрифт» в панели настроек, меню доски и палитра команд.
- `chrome/inspector/StyleTab.svelte` — вкладка «Оформление»: готовые наборы (`PRESETS`), цвета через общую палитру `ui/ColorPicker.svelte` (HSV, `#hex`, пипетка `EyeDropper`, недавние цвета), ползунки с прореживанием правок (в документ — не чаще раза в 66 мс, значение на экране — сразу), копирование и вставка оформления. На узком экране панель становится листом снизу.

## Код, плееры, превью

- **Запуск JavaScript** (`run.svelte.ts`) — в `Worker` из `data:`-адреса. У такого потока «пустое» происхождение: ему недоступны куки, хранилище и API доски, запросы к серверу SPACE отклоняются CORS. `console.*` перехватывается и выводится под кодом, значение последнего выражения показывается как в консоли, бесконечный цикл обрывается через 5 секунд (`terminate`), вывод ограничен 200 строками. Вывод видит только тот, кто запустил.
- **HTML-предпросмотр** — `iframe srcdoc` с `sandbox` без `allow-same-origin`.
- **Плееры сервисов** (`embeds.ts`): адрес страницы Spotify, SoundCloud, Figma, Twitch, CodePen, Google Документов/Таблиц/Презентаций/Форм/Диска, X, Loom и Miro превращается во встраиваемый адрес — только по известным шаблонам, произвольный ввод в `src` не попадает. Такие ссылки сразу показываются плеером. Если щёлкнуть внутрь плеера, узел не выгружается при прокрутке — музыка не обрывается. Видео YouTube, VK, Rutube и Vimeo — отдельный тип `video`.
- **Превью ссылок** (`server/unfurl.ts`): сначала API известных сайтов (GitHub — репозиторий, issue, PR с `GITHUB_TOKEN` или без; Википедия; npm; Steam; YouTube oEmbed), затем `<head>`: Open Graph, Twitter Cards, JSON-LD (в том числе `@graph`), oEmbed-ссылка, лучший значок. Страницы-проверки «вы не робот?» (Cloudflare) превью не считаются. Короткие «факты» (★ звёзды, язык, статус PR, цена) показываются чипами на карточке.

## Сервер

- **`index.ts`** поднимает HTTP и WebSocket на одном порту. Для WebSocket проверяется `Origin` (тот же хост; за прокси при `TRUST_PROXY=1` — `X-Forwarded-Host`), а ping каждые 25 с убирает зависшие соединения. Раз в 6 часов идёт обслуживание: окончательно стираются доски, удалённые больше 30 дней назад, чистятся кэш превью ссылок, старые сессии и ссылки входа. По `SIGINT`/`SIGTERM` сервер дописывает несохранённое, делает снимки и закрывает базу, так что перезапуск на Railway ничего не теряет.
- **`collab.ts` (Hocuspocus).** Имя документа — это id доски. При подключении сервер читает куку и определяет роль. Зрителю даётся соединение только для чтения, и его правки отбрасывает сам сервер, а не только интерфейс. Когда все уходят, документ выгружается из памяти, и перед этим делается снимок. Правки со стороны сервера (например, восстановление из истории) идут через `openDirectConnection` и сразу доходят до всех подключённых. Когда права меняются (доступ по ссылке, роль, заморозка, блокировка), `kickAll` / `kickUser` закрывают не только соединение Hocuspocus, но и сам WebSocket (код 4205): иначе клиент оставался «в сети», но правки перестали бы ходить. Клиент переподключается, проходит авторизацию заново и перечитывает свою роль и права (`refreshAccess`), так что интерфейс сразу знает о новом доступе.
- **`history.ts` — снимки.** Снимок делается после ~10 минут активности, при выгрузке доски, перед восстановлением и вручную (с подписью). Старые снимки прореживаются так: за последние 48 часов хранятся все, до 30 дней — по одному на час, дальше — по одному на день. Подписанные снимки не удаляются. Из снимка можно восстановить всю доску или только выбранные узлы — это приходит всем участникам одной правкой. Перед восстановлением сохраняется снимок «Перед восстановлением», так что откат тоже можно отменить. Ещё из снимка можно сделать новую доску.
- **`files.ts` — файлы по содержимому.** Адрес файла — его sha256: `storage/files/ab/<hash>`. Одинаковый файл хранится один раз, отдаётся потоком с поддержкой `Range` (перемотка видео) и кэшируется навсегда, потому что содержимое по адресу не меняется. Загрузка пишется во временный файл и хешируется на лету.
- **`boards.ts`.** Роль человека на доске (`viewer` < `commenter` < `editor` < `host` < `owner`) — максимум из его личной роли участника, ссылки-приглашения, по которой он пришёл, и общего доступа по ссылке (выключен, просмотр, комментарии, правка). Заблокированный участник не входит никак. Открыл доску по ссылке — стал участником, и доска появилась у него на главной. Что можно человеку, считает `permsOf(role, settings)`: правка (на замороженной доске — только хостам), комментарии, чат, приглашения, управление, восстановление версий, копирование. Комментаторы и зрители подключаются к `/collab` только для чтения, а комментарии и сообщения чата пишут через API (`POST /api/boards/:id/comments`, `/chat`) — сервер сам вносит их в документ. Превью досок хранятся в `storage/thumbs/<id>.webp`, их рисует и присылает клиент.
- **`ranks.ts`.** Ранги аккаунтов (гость, участник, особый, администратор, владелец сервера) и их лимиты: своих досок, размер файла, место под файлы, участников на доске, право создавать доски, загружать и приглашать. Лимиты проверяются при создании и копировании досок, загрузке файлов и входе новых участников. Приглашения на сервер (код, ранг, число входов, срок), режим регистрации (открыта, по приглашению, закрыта), список людей для администраторов, смена ранга и блокировка (человек сразу отключается от всех досок — `kickUser`), передача владения сервером. Менять можно только тех, кто ниже тебя по рангу, а администраторов назначает только владелец.
- **`auth.ts`.** Вход без регистрации: имя и цвет создают аккаунт и долгую httpOnly-куку. Логин и пароль (scrypt) можно задать позже. Есть одноразовая ссылка входа с QR-кодом: она живёт 10 минут, а в базе хранится только её хеш. Новый аккаунт получает ранг по правилам `rankForNewUser`: код приглашения на сервер, живое приглашение на доску (гостем) или ранг новичков; при закрытой регистрации — отказ. `SPACE_INVITE_CODE` по-прежнему работает как постоянный код с рангом «участник».
- **`unfurl.ts`.** Превью ссылок с кэшем в базе, а также проверка, разрешает ли сайт показ во фрейме.
- **`presence.ts`.** Кто сейчас на какой доске — для аватаров на главной. Эти данные живут только в памяти.
- **`config.ts`.** Настройки из окружения и `.env` (рядом с проектом); относительные пути — от папки проекта, `~/` — от домашней. Папка данных создаётся с правами `0700`. Занятый порт или нет прав на адрес — понятное сообщение и код выхода 78 (systemd не перезапускает службу впустую). По `SIGINT`, `SIGTERM` и `SIGHUP` (закрыли окно терминала) сервер сначала сохраняет доски, потом выходит.

## Запуск и Linux

- **`scripts/prepare.cjs`** — общая подготовка для `npm start`, `dev`, `test`, `e2e`: проверяет версию Node, при необходимости ставит зависимости и пересобирает клиент (по отметке сборки), так что после обновления архива достаточно просто запустить.
- **`start.sh` / `start.cmd`** — запуск двойным щелчком. `start.sh` находит Node и в менеджерах версий (nvm, fnm, volta, mise, asdf), работает из любой текущей папки и по символическим ссылкам.
- **`scripts/service.ts`** — служба пользователя systemd (`npm run service`): юнит с правильным экранированием путей (пробелы, `%`, `$`), путь к Node, переживающий обновления, ярлык `.desktop` в меню приложений, подсказка про `loginctl enable-linger`. Без systemd — объясняет, как запускать иначе.
- **Docker** — `Dockerfile` (Node 26, сборка в два этапа, проверка `/api/health`) и `compose.yaml` с томом для данных.

## Безопасность

- **CSRF.** Каждый изменяющий запрос должен нести заголовок `x-space: 1`: чужой сайт не может его поставить без CORS. Кука сессии `httpOnly` и `SameSite=Lax`, а по HTTPS — ещё и `Secure`.
- **Права проверяет сервер:** роль выясняется в каждом запросе API и при подключении к `/collab`. Режим только для чтения у зрителя и комментатора (и у всех, кроме хостов, на замороженной доске) тоже обеспечивает сервер. Смена роли, блокировка, передача доски, заморозка и смена доступа по ссылке разрывают соединения с доской, и при переподключении права считаются заново; смена ранга или блокировка на сервере отключают человека от всех досок.
- **Ограничение частоты:** вход — 10 попыток в минуту, создание гостей — 30 в час, превью ссылок — 90 в минуту.
- **SSRF.** Превью ссылок ходят только во внешний интернет: адрес проверяется уже после DNS (в `lookup` сокета), поэтому подменой DNS сервер нельзя направить в локальную сеть. Для домашней сети это можно разрешить переменной `UNFURL_PRIVATE=1`.
- **Загруженные файлы.** Типы, которые браузер мог бы исполнить как страницу (HTML, SVG, XML, JS), отдаются с `Content-Security-Policy: sandbox` и `nosniff`.
- **Markdown** обрабатывается с `html: false`: HTML в тексте экранируется. Внешние ссылки открываются в новой вкладке с `rel="noopener noreferrer"`.

## Офлайн и надёжность

- У каждой открытой доски есть копия в IndexedDB. Без сети доска открывается из неё, правки копятся локально и сами сливаются с сервером при подключении: это свойство CRDT, отдельной логики синхронизации нет.
- Сервер хранит документ целиком, и снимки истории дают точки возврата. Резервная копия — это папка `storage` (`space.db` вместе с `files/` и `thumbs/`).
- Ограничение: сервис рассчитан на **одну реплику**, потому что открытые доски живут в памяти процесса. Для нескольких реплик понадобился бы общий канал между ними (например, Redis-расширение Hocuspocus). Для личного и командного использования это не нужно.
- Файлы автоматически не удаляются: на них могут ссылаться снимки истории.

## Почему такие решения

| Решение | Почему | Что отвергнуто |
| --- | --- | --- |
| Svelte 5 (руны) | Реактивность на уровне полей без виртуального DOM: тысяча узлов и правка одного поля стоят одного обновления DOM. Маленький бандл. | React (сравнение деревьев при каждом кадре жеста), чистый canvas-движок (теряются текст, выделение, IME, видео и iframe) |
| DOM вблизи + canvas издалека | DOM бесплатно даёт Markdown, редактор, ввод на любом языке, видео, iframe и доступность. Canvas — там, где DOM не справляется: тысячи узлов на экране. | Только DOM (тормозит издалека), только canvas (своя вёрстка текста и редактор) |
| Yjs + Hocuspocus | Слияние без конфликтов и работа без сети; посимвольное слияние текста; отмена только своих правок; готовые хуки прав, соединения только для чтения, отложенное сохранение, правки с сервера. | Своя синхронизация JSON-патчами (конфликты, нет офлайна), OT (нужен центральный сервер для каждой операции) |
| `node:sqlite` | Встроен в Node: на Windows не нужно собирать нативные модули и ставить Visual Studio Build Tools. Одна база в одном файле, легко сделать копию. | better-sqlite3 (нативная сборка), Postgres (отдельный сервис) |
| Hono | Маленький и быстрый, работает со стандартными `Request`/`Response`; входные данные проверяет zod. | Express (медленнее, свои req/res вместо стандартных) |
| TypeScript без сборки на сервере | Node ≥ 22.18 сам убирает типы: сервер запускается из исходников, а типы из `src/shared` общие с клиентом. | tsc/esbuild-шаг для сервера |
| Файлы по хешу | Дубликаты хранятся один раз, кэш вечный, файл не может «подмениться». | Имена файлов и UUID |
| Клавиши по `e.code` | На русской раскладке `Ctrl+Z` приходит как «я»: по символу горячие клавиши молча не работали бы. | `e.key` |

## Тесты

- `npm test` (Vitest) — модульные тесты: геометрия, распознавание фигур, Markdown и флажки задач, API сервера (вход, CSRF, роли и доступ по ссылке, импорт, экспорт, история), экранирование путей службы Linux, счётчики и комментарии, свои цвета, языки кода, целостность всех шаблонов, разбор превью ссылок (og, JSON-LD, oEmbed, опасные адреса), адреса плееров сервисов.

- `tests/unit/perms.test.ts` — роли и права на доске, ссылки-приглашения, ранги и лимиты, приглашения на сервер, блокировка.
- `tests/e2e/perf.ts` — замер FPS на большой доске (`tests/e2e/seed.ts` создаёт доску нужного размера). `tests/e2e/shots.ts` — снимки экранов для проверки вида.
- `tests/unit/play.test.ts` — игровые объекты: длительности, границы счётчика, секундомер, монетка, колода, очередь ходов, чек-лист, облако слов, случайный выбор. `tests/unit/die3d.test.ts` — геометрия 3D-кубика (выпавшая грань в покое смотрит на зрителя при любом наклоне).

## Как добавить новый тип узла

1. В `board/model.ts` добавьте тип в `NodeType` и задайте ему значения по умолчанию в `defaults()`. Если высота должна подстраиваться под содержимое, добавьте тип в `FIT_TYPES`.
2. Создайте `board/nodes/MyNode.svelte` и зарегистрируйте его в `COMPONENTS` в `board/ui/NodeHost.svelte`.
3. Опишите, как узел выглядит издалека, — ветка в `board/scene.ts`.
4. Если узел можно поворачивать или соединять стрелками, добавьте его в `ROTATABLE` / `CONNECTABLE` в `board/ui/Overlay.svelte`. Если форма узла не прямоугольная, добавьте попадание в `board/hit.ts`.
5. Действия для узла добавляются в `board/menus.ts` (контекстное меню) и в `board/chrome/ContextBar.svelte` (панель над выделением).
6. Чтобы узел появился в библиотеке и палитре команд — строка в `BASIC` в `board/library.ts`; в шаблонах его можно использовать через построитель `TB` в `board/templates.ts`.
7. Если несколько человек могут менять значение одновременно (как голоса или счётчик), храните вклад каждого в своём поле (`<префикс>:<uid>`) и складывайте при чтении.
8. Чтобы узел участвовал в логике — события в `triggersFor`, действия в `actionsFor` и их выполнение в `board/logic.svelte.ts`; число и «готово» для входов других узлов — в `numValue` / `doneShare` в `board/nodes/values.ts`. Если у узла свои настройки, опишите их поля в `board/inspect/build.ts` (панель настроек), а главные действия — в `board/nodes/widgetItems.ts` (быстрое меню над объектом).
